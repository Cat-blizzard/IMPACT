# P4 / 阶段 A 二次审查修复（2026-09-17）

本轮修复针对 20b3576 的复审反馈。源码与回归验证不等同于新版本的完整构建、飞行验收或端侧验证；既有 CPU/GPU 飞行记录仍绑定各自历史提交。

## 变更

- P4 DESCEND 删除遗留 60 秒提前结束分支。LAND、DESCEND、FAILSAFE_WAIT 使用首次进入终止阶段起算的配置预算，阶段切换不延长期限。正常落地仍可提前完成；任务失败不会因落地改记成功。P5 自己覆盖的旧生命周期不在本轮修复范围。
- 仲裁状态升级为 schema_version=2。authorized 表示当前时间和输入状态下的有效授权，不再表示内存里存在授权对象。TRACK 与 BRAKE 仍由 mode 区分。
- 每条实际发出的 MAVROS 目标记录精确纳秒时间戳、坐标、朝向和 TRACK 所用的会话、请求、轨迹、命令及授权时限；记录实际接收到的授权修订时间、本地回调/决策序号和输入年龄，区分同一仿真时刻内的授权与撤销先后。变换失败或未发指令时 emitted=false。
- 新增 scripts/audit_stage_a_authorization.py，读取实际 SQLite rosbag 的授权、已认证 B-spline、PositionCommand、仲裁状态及最终 MAVROS 目标。检查全量输出关联、TRACK 的有效授权和命令来源，并分别核验实际执行过轨迹的撤销及授权过期行为。
- 阶段 A 不再用 CERTIFY/REVOKE 事件存在代替执行证明。审计发现违规为 FAIL；缺消息、旧遥测、未覆盖撤销/过期或缺少关联输出为 INCOMPLETE，阶段 A 在其他条件满足时显示 REVIEW_REQUIRED，退出码仍非零。被拒候选不算已执行轨迹的撤销。

## 证据边界

该审计验证录制到的软件授权和最终 MAVROS 指令输出。它不证明飞控已执行每条指令、不重建完整 TF 几何链、不证明物理停距或真实飞行动力学；结果明确保留 physical_stop_verified=false。制动后仍可能输出合法保持/制动目标，不能把“仍有目标发布”直接当成继续执行旧轨迹。

历史 bag 缺少新版关联遥测，不能靠补写 JSON 升级为 PASS。正常任务如果没有实际覆盖撤销或过期，也不能借事件标签补齐覆盖。需要在冻结版本上安排相应验证并保留完整录制。
