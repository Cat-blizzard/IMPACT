本轮以代码提交 37ffc80 为起点修复控制与验收缺陷，提交前合入远端 b3ada48 / 0cfbe63 的 GPU 退出修复及诊断证据。以下是源码和回归测试结果，不是新的飞行验收；不改写 b88288f 的 CPU P4 历史运行结果。

## 修复内容

| 问题 | 修改 |
|---|---|
| 方向完整性只检查最近障碍，加入障碍可能反而放行 | P16 对所有可能决定最差裕度的采样点/障碍方向计算 AL−PL；分块并用保守距离/PL 上界剪枝，保持几何碰撞检查 |
| 授权回调先发现时钟回退时未清理旧制动目标 | 每次时间不连续递增重置代数；仲裁器按代数清理，覆盖回调先后与重复回退 |
| P16 HOVER/ACTIVE 绕过飞控健康门 | 持续核验 ExternalNav、FCU/EKF、armed/GUIDED 及状态新鲜度；故障进入终止，保留 FCU 已有 LAND |
| P4 故障后降落改记 PASS | 保留任务失败原因；降落解除武装只确认终止，不将任务改成成功；runner 同时检查任务字段和必要检查项 |
| 总任务超时饿死 LAND/DESCEND/FAILSAFE_WAIT | 任务预算与终止预算分开；终止阶段共用首次进入时的 90 秒期限，阶段切换不延长；runner 预留对应时间 |
| FAILSAFE_WAIT 通信恢复后不再请求降落 | 新鲜 armed 且未处于 LAND 时恢复降落流程；已有 LAND 则继续等待 |
| 过期 disarmed 被当作终止确认 | 终止结果要求 FCU 状态新鲜；P16 正常降落完成还要求高度数据新鲜 |
| 冒烟只检查相邻样本间隔 | 同时检查首帧延迟、末尾静默、完整观察时长和有效健康消息 |
| 已到目标但终止超时的运行被汇总器改记成功 | 汇总 PASS 同时要求 mission.status 和 evaluation.status 为 PASS；终止已确认的失败仍保留为有效失败样本 |
| 阶段 A 读取不存在的 evaluation.status | 独立评估器明确输出 PASS/IN_PROGRESS/FAIL，基于样本量、碰撞及有限数值；任务结果仍单独判断 |
| 地图文件名/话题字符串可伪造内容通过 | 取消文件名推断；只读实际 SQLite bag 的精确话题类型和非零消息数，记录数据哈希，最多返回 READY_FOR_REVIEW |
| 地图审计所需话题未录制 | 补录 information_cloud、navigation_map、exploration/status 和 EGO occupancy_inflate，保留 TF 与信息地图 |

## 地图审计边界

现在的 diagnose_stage_a_maps.py 是证据盘点器，不能仅凭消息存在证明地图内容、时间/TF 对齐、膨胀或可达性正确。即使原始数据齐全，也只输出 READY_FOR_REVIEW，且 map_content_verified=false。

阶段 A 的其他检查都通过而只缺地图内容验收时，结果为 REVIEW_REQUIRED，命令保持非零退出。缺数据或其他检查失败则为 FAIL。未经内容验证的数据不能通过 MAP_CONTENT_VERIFIED，也不能放行正式矩阵；本次没有增加手写 PASS 的绕过入口。

后续需要依据实际飞行 bag 核查共享地图与 EGO 碰撞地图内容，并完善独立内容验证流程。旧 P5 FAIL、阶段 A/B 的飞行验收和正式 120 次矩阵状态没有因此改变。合入的独立 GPU 报告记录一次开发飞行通过，仍不是三次冷启动稳定性验收；该结果也不等于本轮修复已重飞。
