## 2. 主比较验证什么？

研究问题：在相同定位、地图、EGO 规划器和 ArduPilot 执行条件下，完整性认证与主动恢复能否在定位退化时改善任务表现？

原仓库已经有定位、完整性估计、PL/AL、轨迹认证和主动恢复算法。本轮发展是把这些能力接入 EGO 最终优化轨迹与 MAVROS/ArduPilot 执行链，增加授权有效期、持续复核、制动和任务恢复管理，并统一实验入口。

这首先是闭环工程扩展。安全性、成功率、恢复收益是否提高，须由服务器实测回答。

## 3. 四组实验的准确含义

| 配置名称 | 图表显示名称 | 主要作用 |
|---|---|---|
| baseline | EGO 基础链路：无完整性硬门、无主动恢复 | 作为主参考，观察加入完整性和恢复后的综合变化 |
| conservative | EGO 固定保守低速 | 检查改善是否可以由固定减速解释 |
| hard_gate | 完整性硬门，无主动恢复 | 消融主动恢复，比较等待与主动运动的差别 |
| recovery | 完整 IMPACT | 完整性硬门＋短段主动恢复＋在线重新认证 |

四组均保留共同的基本碰撞、动力学、数据新鲜度、指令和终止检查。baseline 的含义是关闭完整性硬门和主动恢复，不是删除全部控制保护，也不是把其传感器或定位配置调差。

EGO 的出处：[原论文](https://arxiv.org/abs/2008.08835)、[官方代码](https://github.com/ZJU-FAST-Lab/ego-planner)。本仓库使用已适配的 EGO 执行链，报告时应说明版本和本地改动。

共同参数必须冻结，conservative 的低速设置为预先声明的策略差异。开发种子 1000—1004 与正式种子 0—9 分开。不得看正式结果后反复调基线参数。

## 4. 主视频：左基线，右完整 IMPACT

### 画面布局

左右两栏等宽，使用相同场景视角、坐标范围、尺寸和播放速度：

| 左侧 | 右侧 |
|---|---|
| EGO 基础链路 / 无完整性层 | 完整 IMPACT |
| 实际飞行或记录状态重建画面 | 实际飞行或记录状态重建画面 |
| 任务进度、真值定位误差、真值净空 | 相同指标，以及认证/恢复状态 |
| PL/AL 可作为只读观察量，注明未参与硬门 | PL/AL/Margin 与执行授权状态 |

真值误差与净空只供评估和视频展示，不反馈给算法。缺失或过期指标显示“无有效数据”，不能以零代替。状态来自日志，不能事后凭画面猜测。

### 希望展示的因果链

1. 正常环境中执行相同任务。
2. 进入退化区域，出现可记录的定位质量/完整性变化。
3. 完整 IMPACT 因认证失败撤销轨迹并制动。
4. 提出恢复意图，EGO 重新规划并认证后执行。
5. 恢复动作后取得新观测，在线重新认证。
6. 条件满足后继续原任务；若不满足，则展示等待、超时或失败。

这是一条待实验验证的展示目标，不是预先写好的实验结局。左侧可以顺利完成，也可以出现偏差、停顿或任务失败，均按记录展示。不得设计成“基线必须撞墙、IMPACT 必须获胜”。

### 同步和剪辑规则

- 选择同一场景、同一配对种子、相同世界/校准/源码和服务器配置的两次任务。
- 两组独立运行，各自沿实际轨迹形成传感器观测；不能用同一段离线观测冒充两套闭环飞行。
- 以任务进入 ACTIVE 的仿真时刻对齐，t=0 定义写入视频说明；记录首次 telemetry 与 ACTIVE 起点之间的偏移。
- 使用相同仿真时间轴和播放倍率。若加速，整段同时加速并显示倍率；不得单独加速一侧或删除其等待时间。
- 一侧任务先结束后保持最终画面，并显示“已完成/已失败/记录结束”；不得把另一侧继续运行的时间伪装为双方仍在飞行。
- 定位误差、净空和 PL/AL 曲线按播放时刻逐步显示，并用游标标出当前时刻。结尾可以显示完整曲线。
- 统一显示“软件在环仿真（SITL）”、服务器硬件及视图来源。当前渲染器是记录状态重建，不是原始 Gazebo 录屏，须明确标注。
- 保存每个剪辑片段对应的运行目录、提交、种子、仿真时间区间、倍率及视频哈希，保留未剪辑记录。

### 状态字幕

建议使用“正常前进”“完整性不足”“制动”“恢复规划”“恢复执行”“重新观测”“恢复任务”“任务超时”等简洁字幕。

字幕必须对应事件。只有新观测之后的任务轨迹通过在线认证，才可标为“恢复任务”；预测协方差下降不能单独作为恢复成功的依据。可利用 `events.jsonl` 的 PLAN_REQUEST、CERTIFY、REVOKE、RECOVERY_STEP_DONE、NEW_OBSERVATION 和 RECOVERY_CONFIRMED 关联画面。

### 结尾结果卡

左右同样展示：是否完成、失败原因、是否确认终止、任务仿真耗时、定位误差、最小真值净空、路径长度、撤销到停止时长。指标缺失时如实标注。

恢复分析补充显示 ΔM = ΔAL − ΔPL。前后可能是不同轨迹、关键点和方向，因此不能把全部裕度增加说成定位精度提高。

## 5. 视频与统计的分工

双栏视频用于解释一轮实际决策过程。四组、三场景、十个配对种子的统计用于判断现象是否重复出现，以及安全、任务完成与耗时之间的权衡。

- 不能以一段精选视频代替 120 次任务结果。
- 可以选择因果过程清楚的一轮作演示，但须披露种子、选择理由和完整矩阵表现，不能声称它代表所有运行。
- 失败、超时、无收益和基线成功均保留；始终停车不能只因零碰撞就判为最好。
- 统计单位是独立任务，不把逐帧样本当成独立实验。
- 工程错误与确认终止的任务失败分开记录；不能因后者表现不好就重试直到成功。

## 6. 可选扩展的边界

### 不确定性自适应减速／停车

如果四组实验和主 demo 已跑通，可评估增加这一工程基线：根据当前定位不确定性调节速度，超过冻结阈值停车，条件恢复后继续。

它用于检验“简单地根据定位质量减速是否已经足够”。尚未实现，不称为已复现的论文方法。加入前需独立定义指标、阈值、滞回、速度映射和超时行为，在开发数据上调参后冻结，并建立新的实验协议；不要混入当前 120 次矩阵。

### 外部公开方法

论文阶段再选择与定位不确定性或可观测性直接相关的方法，核查传感器、地图、控制接口和任务假设。只换一个避障规划器，不能直接回答完整性与主动恢复的贡献。

原 P10 的专用速度执行链与新 ArduPilot 链不同，不能直接拿两段阶段视频作算法优劣证据。
